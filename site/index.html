01 / THE PROBLEM

Memory is not the hard problem. Trust is.

An AI coding assistant is a brilliant new hire with daily memory wipes. Three failures keep costing you.

01

Every session starts at zero

Architecture decisions, API constraints, the thing you argued about last week — gone. The agent steps on landmines you already cleared.

02

Dead conclusions resurrect

You migrated from SQLite to PostgreSQL. Raw transcripts still return the old decision as if it were current — and the agent reintroduces the problem you fixed.

03

Disputes close silently

Both sides of an unresolved timeout debate sit in the transcript. Retrieval returns half of each, the agent picks one, and invents closure.

Hand-maintained memory rots. Vector search is status-blind. The missing piece is a lifecycle for “what still counts”.

02 / THE METHOD

A ledger, not a chatbot diary.

One claim is one standalone statement plus a status and provenance. Around it: two writes, three reads, one state machine.

01 — RECORD

Capture at decision time

If a new claim overlaps a current one, the write is refused. Supersede the old claim or declare the dispute. No silent wins.

$ claim record "Use PostgreSQL" --topic database
possible conflict with current claim(s):
  clm_9f2a6c1d4e8b73a0
02 — BRIEF

Read as a byte-bounded brief

Deterministic, rebuildable, and honest about omissions: bytes used, budget, and how many entries were dropped.

05 / BOUNDARIES

What it refuses to be.

The refusal list is part of the design. Every “no” keeps the next reader from trusting the wrong thing.

×Not this

  • No built-in vector database.Semantic retrieval hides staleness and conflicts; the core stays lexical. A host RAG index is optional and never authoritative.
  • No fully automatic capture.Unreviewed auto-memory is a poisoning surface.
  • No daemon, no cloud sync.Local ownership is the floor; knowledge should not follow a vendor.
  • No truth detector.Citations prove a quote exists, not that the conclusion is correct.

✓This

  • A local MCP server and an Agent Skill.Five tools, including review-only suggestions and status-filtered recall; installable into Claude Code or Codex.
  • A single JSONL authority.Briefs, pages and exports are disposable views, rebuilt from the store.
  • A deterministic Python API.Python 3.9+, zero third-party dependencies, no import-time I/O.
  • A demo you can audit.The browser UI calls the same ClaimStore as the CLI and MCP server.
  • An optional RAG evidence layer.A host retriever can supply passages; every hit must resolve to a claim and pass the same status filter.
  • A writer lock, backups and auditable removal.Concurrent writers serialize; snapshots verify against a manifest; redact and delete leave an audit entry and a pre-change backup by default.

The full boundary list lives in the README: no built-in model service, no hosted web UI, no cross-machine sync, no universal compaction hook.
