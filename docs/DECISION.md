# 为什么保留这个仓库，以及它不再是研究

**日期** 2026-11-02
**结论** 研究命题终止；仓库作为工程实现保留。

---

## 1. 原本要回答的问题

> Agent 会不会照着已被推翻的结论行动？把状态（现行 / 已过期 / 有争议）做成一等公民，能不能阻止？

这个问题的答案已经存在，而且比本仓库给出的证据强一个量级。

## 2. 已有工作

| 论文 | 日期 | 覆盖了什么 |
|---|---|---|
| **Revoked but Still Authoritative**（arXiv:2609.08258） | 2026-09-08 | 5 个记忆系统 × 9 个模型 × 9 个策略场景。结论：没有任何系统默认执行撤销；标签可见时，失效事实仍被返回、排在替代事实之前，并让 agent 执行不安全动作。 |
| **Governed Persistent Memory**（arXiv:2608.12476） | 2026-08-12 | 可审计的双时间轴状态机、source-bound admission、conflict isolation、retraction 后不可复活、fail-closed release；3,600 例冻结基准。 |
| **MemTX**（arXiv:2607.23929） | 2026-07-27 | “一次记忆写入不是一次信念提交”；写入分级、validate-and-commit、级联修复。 |
| **Memory, Know Your PLACE**（arXiv:2610.25179） | 2026-10-18 | write-side state certification + read-side authorization。 |

四篇论文合起来，覆盖了本仓库 v1 的全部机制与 v2 设计稿的全部方向。

## 3. 为什么当初没发现

`docs/design-v2.zh-CN.md` §12 做的是 **GitHub 竞品核查**：数星数、看产品定位。它回答的是“有没有人做成了产品”，没有回答“有没有人做完了研究”。

在一个研究相邻的方向上，**先验知识在论文里，不在仓库里**。检索面选错，结论就会是“定位空白”。

这不是信息不足，是**检索对象错误**。

## 4. 现在这个仓库是什么

一个零依赖、单文件、可嵌入的本地实现，包含：

- 三态声明式生命周期（`current` / `superseded` / `disputed`）
- 写入时冲突拒写，冲突必须显式替代或声明争议
- 有效轴 + 录入轴的双时间轴，`--at` 重建任意时点的信念
- `depends_on` 前提坍塌后派生 `unmotivated` 标记
- 字节预算硬契约，省略条目数可核对
- 421 个测试，零第三方依赖，零网络调用

它**不主张新颖性**。它的价值是：决定“什么算现行”的每一条规则，都能在一个文件里读完并审计。

## 5. 已知的、写在这里的失败

- **冲突检测是词法的。** `find_conflicts` 用 token 重合率判断，会漏掉“Postgres 禁用了”与“用 Postgres”这类真冲突，也会误报同词不同事。
- **争议切片表现最差。** 在仓库自带基准的 conflict/controversial 切片上，状态感知的 Recall@1 是 0.00，基线是 0.75；MRR 从 0.8125 降到 0.1750。聚合表掩盖了这个双峰结果，[意图切片](../benchmarks/benchmark-results.md)才看得出来。
- **基准是合成数据。** 24 条 query、40 个合成 session、零模型调用，且与 demo 共用同一份场景数据。

## 6. 什么条件下才该用它

- 你需要一个**能读完、能审计、零依赖**的本地声明式状态层；
- 你接受冲突检测只做“提示”，真正的判断由人或宿主模型完成；
- 你不要求它替你判断语义真值。

不满足这三条，用已有的记忆系统或直接上 GPM / MemTX 那一类方案更合适。

## 7. 这次留下了什么

不是代码，是一个顺序：

> **先写命题，再查文献，然后才决定要不要建。**

这个仓库是按“先建、后查”的顺序做出来的。它花了十天；核查花了两小时；如果顺序反过来，那十天可以省下。
