# Jev-first：让项目顺应模型，而不是让模型顺应项目

**日期** 2026-11-02
**状态** 生效。本文件优先于 `design-v2.zh-CN.md`。

---

## 0. 一句话

> 旧项目是**数据层**，不是产品层。
> 产品层是：**一组强类型问题 + 一个确定性策略 + 一条可校准的决策日志。**
> 这三样都必须能脱离任何一个生成模型独立存在。

判断某个功能该不该留，只问一句：

> **它是否让"换模型不换记忆"更容易成立？**

不成立就砍。

---

## 1. 为什么是 Jev，而不是"接一个 LLM"

| 能力 | LLM | Jev |
|---|---|---|
| 输出 | 自由文本 | 闭集（choice / score / noul） |
| 概率 | 自称的置信度，不可校准 | 训练目标就是校准（RLCD） |
| 可审计 | 只能存一段解释 | 可以阈值化、统计、画校准曲线 |
| 单次成本 | 高 | $0.042/MTok 输入 |
| 可复现 | 低（采样） | 高（闭集判定） |

只有"闭集 + 概率"这两条同时成立，**记忆的准入才能变成一个可验证的数字**，而不是一句"模型觉得可以"。

**但实测延迟是 1.6–4.4 秒（文档标称 70–500ms）。** 所以：

- Jev 只能放在**写入时**或**动作前**，不能放在交互式读路径；
- 一次请求必须问完所有问题（Jev 支持并行多问题），不能一个 claim 一次调用。

这两条是硬约束，架构必须绕着它们长。

## 2. 砍 / 留 / 降级

判断标准只有一条：是否服务于"换模型不换记忆"。

| 模块 | 处置 | 理由 |
|---|---|---|
| **wiki**（`_internal/render_notes.py`、`KnowledgeStore`） | **砍** | 第三条读路径，是文档合成，不是记忆判定。换模型时它只会增加漂移面 |
| **RAG adapter / 向量索引** | **砍** | Jev 直接判文本。多一层不可审计的检索，等于把可解释性换成召回 |
| **demo server / static / 站点 / 品牌资产** | **砍** | 不承担任何判断，占仓库 90% 体积 |
| **Context Gateway**（豆包/JSONL 摄入） | **降级为脚本** | 是录入便利，不是核心。留在 CLI 里，不进主路径 |
| **`find_conflicts` 词法检测** | **替换** | 探针已证：C4（"PostgreSQL 被禁"/"用 PostgreSQL"）它看不见。这是它存在的唯一理由，理由没了 |
| **`depends_on` / unmotivated** | **降级** | 有价值，但属于第二阶段。现在做就是让 Jev 去迁就旧模型 |
| **状态机 current/superseded/disputed** | **留，降为数据** | 它是记忆的内容；但**不再作为过滤器**，只作为 Jev 的输入事实 |
| **字节预算** | **留，升级** | 变成"在预算内最大化期望价值"的选择器，正好接校准概率 |
| **`--at` 时点重建** | **留** | "当时的信念"是记忆的本质，且与模型无关 |
| **MCP server** | **留** | 分发面。换模型的操作面就在这里 |
| **CLI** | **留** | 同上 |

> 砍掉的部分不立即删除，先移出主路径（README、入口、文档）。删除等新核心跑通再做——留一个可回退的窗口。

## 3. 新核心：三个部件

```
候选记忆 ──▶ 组题 ──▶ 一次 Jev 请求 ──▶ 确定性策略 ──▶ 决策 + 日志
             │                              │
             └── 状态只是文本里的事实       └── 阈值/代价矩阵，可版本化
```

### 部件一：问题库（`jev_first/questions.py`）

每条决策一次请求，问题按 claim 批量生成：

| 问题 | 类型 | 含义 |
|---|---|---|
| `applies::<id>` | noul | 这条记忆约束当前任务吗 |
| `holds::<id>` | noul | 它现在还有效吗 |
| `governing` | choice | 哪一条应当支配这个任务（含 `none`） |
| `contradiction` | noul | 候选之间存在语义矛盾吗 |

**一次请求问完**，这是对 1.6–4.4s 延迟的唯一正确回应。

### 部件二：策略（`jev_first/policy.py`）

概率不做解释，做**决策**：

```
score = p(applies) × p(holds)
score ≥ 0.60          → admit
0.30 ≤ score < 0.60   → review（仍然返回，带标记）
score < 0.30          → exclude
contradiction ≥ 0.70  → 所有相关条目强制 review，禁止自动排除
```

**非对称代价写死在策略里**：错误抑制比错误保留更坏，因为抑制是静默失败。

阈值和代价矩阵是数据，不是代码常量——它们必须可版本化，因为校准要能回放。

### 部件三：决策日志（`jev_first/log.py`）

每次决策追加一行：

```json
{"at": "...", "model": "jev-1.14.0", "policy": "v1", "budget": 2048,
 "entries": [{"claim_id": "...", "p_applies": 0.91, "p_holds": 0.88, "action": "admit"}],
 "contradiction": 0.12, "governing": "clm_...", "used_bytes": 1043, "omitted": 2,
 "latency_ms": 2310}
```

**这条日志是"换模型不换记忆"的凭证**：换模型后，同一批记忆、同一套问题，产出的概率分布可以被直接比较。

### 3.4 实测约束（2026-11-02）

同一个请求（4 条 claim / 10 个问题），两次运行：

| 运行 | 延迟 |
|---|---:|
| 第一次 | 11,213 ms |
| 第二次 | 2,902 ms |

2 个问题的探针是 1.6–4.4 s。由此定下四条：

1. **延迟由问题数驱动，且方差极大**（同一请求差近 4 倍）。
2. **单请求 claim 上限暂定 6 条**（约 12–14 个问题）。超过就先做候选裁剪，否则尾部延迟不可用。
3. **概率不是逐位可复现的**：两次运行 `clm_analytics` 分别是 0.89/0.63 和 0.90/0.68。决策稳定，数值不稳定——所以校准必须按分布看，不能按单点看。
4. 尾部 11 秒意味着：只可用于写入时与批处理，**永久排除交互式读路径**。

### 3.6 冲突定位（取代全局信号）

实跑发现：全局 `contradiction` 是粗粒度的——它把无冲突的记录也压成 review。

现行流程改为两段式：

1. **Stage 1**：每条记录**单独**面对任务，问一次 `admit` choice。集合里其他记录的冲突不再污染它的答案（这正是被退役的 `applies`/`holds` 存在的理由）。
2. **Stage 2**：对**被准入**的记录两两提问 `relation`（契约中 VALIDATED 的问题，逐字使用；pair state 与 30 对实验格式完全一致）。确认矛盾的每一对，双方进 review；其余记录保留 stage-1 结论。
3. **Stage 3**：`governing` 只能在**未卷入冲突**的幸存者上把 review 提升为 admit。

pair state 与任务无关，因此**成对判断跨任务缓存**——第一次贵，之后近乎免费。
全局 `contradiction` 问题在契约 v1 中保留定义，但引擎不再使用；契约 v2 将正式移除。

实测（2026-11-03，4 条记录）：11 个请求并发，4.7 s；定位出正确冲突对（全部 PostgreSQL vs analytics 禁用），同时模型把一个边界对（must-PostgreSQL vs SQLite-deprecated）判为矛盾——与 30 对实验中措辞稍异的 P11（complementary）相反。边界对的翻转正是校准视图要跟踪的东西。

### 3.5 governing 规则（v1.1，已被 3.6 收编为 stage 3）

第一次运行时发现：Jev 给出 `governing=clm_analytics (0.96)`，但策略完全忽略它，把这条压成了 `review`。

修正：`governing` 命中且置信 ≥ 0.80 → 直接 `admit`，`contradiction` 仍单独上报。

理由：admit 不是抑制。矛盾作为字段可见，不算静默失败；忽略模型最有价值的输出，才是浪费。

## 4. 这套东西如何回答目标

| 目标 | 由哪个部件承担 |
|---|---|
| 记忆不随模型变 | 记忆存成模型无关的文本 + 状态；判断由 Jev 做，不由生成模型做 |
| 换模型后可验证 | 决策日志里同一套问题的概率分布，换模型前后可直接对照 |
| 可审计 | 策略阈值 + 概率 + 输入候选集，三者足以复算 |
| 低成本 | 一次决策一次调用；输入按分钱计 |

**端到端的一句话**：

> 换的是生成模型，不换的是**问题集、策略、日志**。
> 只要这三样不变，记忆的语义就不随模型漂移。

---

## 5. 不做

- 不做向量检索。Jev 直接判文本。
- 不做 third read path。`brief` 和 `search` 合并成一个 `decide`。
- 不做多模态、图谱、云端同步。
- 不在延迟问题解决前，把 Jev 放进任何交互式路径。
- 不在"换模型是否真的破坏行为"这一前提被验证之前，扩功能。

## 6. 下一步（唯一一个）

跑 **30 对真实 claim** 的关系判定：

- 真冲突召回 ≥ 0.70
- 错误抑制 ≤ 0.10

过不了，这个方向就停。过了，再把 `decide()` 接到 MCP 上。
